# 楓藝諮詢後台（簡易 CRM）設計規格

日期：2026-09-29　狀態：已確認，實作中

> **2026-09-29 變更**：拿掉 Email 欄位（官網表單、試算表、後台都不收）；後台列表加上「需求說明」欄；秘密碼改成站長自訂的好記字，首頁網址加 `#秘密碼` 會轉到後台，並加上「10 分鐘內錯 30 次就暫時擋掉」的保護。新增「服務縣市」欄（官網必填）。列表可直接改進度與備註。**使用者要求加入刪除功能**（列表與詳細資料都有，需二次確認，刪除後從試算表移除、無法復原）。

## 1. 目標
- 官網諮詢表單改為「真的送出」：資料存進 Google 試算表，不再打開客人的 Email。
- 有新諮詢時，寄 Email 通知站長。
- 站長（只有一人）用一個「秘密網址」直接打開後台，不用登入頁；在後台查看諮詢、更新進度、寫備註、手動新增、匯出資料。

**成功標準**
- 客人送出表單後看到成功訊息，試算表多一筆資料，站長收到通知信。
- 站長打開書籤就進入後台，手機、電腦都能用；改完進度或備註，重新整理後資料還在。
- 沒有秘密網址的人打不開後台資料。

## 2. 已確認的決定
| 項目 | 決定 |
|---|---|
| 使用者 | 只有站長一人 |
| 進入方式 | 秘密網址，不做登入頁（使用者已了解風險並選擇此方案） |
| 資料存放 | 站長的 Google 試算表 |
| 進度階段 | 新諮詢 → 已聯絡 → 已場勘 → 已報價 → 已成交 → 施工中 → 已完工，另有「沒成交」 |
| 通知信 | 要，收件信箱由使用者之後提供 |
| 匯出 | 後台可以直接匯出 |
| 不做 | 多人帳號、權限、刪除紀錄、報價單產生 |

## 3. 架構

```
官網 index.html ──(送出表單)──┐
                              ▼
                  Google Apps Script 網頁應用程式 ──讀寫──► Google 試算表「楓藝諮詢紀錄」
                              ▲                    └──► 寄通知信（MailApp）
後台 admin.html#k=秘密碼 ──────┘
```

- **Google 試算表**：資料本體，站長也可以直接打開來看。
- **Apps Script**：寫在試算表裡的小程式，部署成網頁應用程式。
  - 執行身分：站長本人
  - 存取權限：任何人（寫入和讀取的權限，由下面第 5 節的規則控管）
- **官網和後台**：都是 GitHub Pages 上的靜態頁面，用 `fetch` 呼叫 Apps Script 的網址。

## 4. 資料欄位（試算表工作表「諮詢」）
| 欄位 | 說明 |
|---|---|
| 編號 | 自動產生，例如 `20260929-0831-a3f` |
| 建立時間 | 送出當下的時間（台灣時間） |
| 來源 | `官網` 或 `手動` |
| 姓名、電話、工程類型、需求說明 | 表單內容 |
| 進度 | 八個階段之一，新資料預設為「新諮詢」 |
| 備註 | 站長自由填寫的一段文字 |
| 最後更新 | 最後一次修改的時間 |

## 5. Apps Script 的功能
所有請求都用 `POST`，內容是 JSON 文字（`Content-Type: text/plain`，避免瀏覽器的跨網域預檢）。

| 動作 | 誰可以用 | 做什麼 |
|---|---|---|
| `submit` | 任何人（官網表單） | 檢查必填欄位，寫入一列，寄通知信 |
| `list` | 帶正確秘密碼的人 | 回傳全部資料 |
| `update` | 帶正確秘密碼的人 | 修改某一筆的進度或備註，並更新「最後更新」時間 |
| `create` | 帶正確秘密碼的人 | 手動新增一筆，來源標為「手動」 |

- **秘密碼**：存在 Apps Script 的「指令碼屬性」`ADMIN_KEY`（32 字元的隨機碼），**不會出現在 GitHub 的程式碼裡**。要換秘密碼時，改這個屬性就好，舊網址會立刻失效。
- **通知信箱**：存在指令碼屬性 `NOTIFY_EMAIL`。還沒設定時就不寄信，其他功能照常運作。
- **防垃圾訊息**：
  - 表單加一個隱藏欄位，機器人填了就直接丟掉
  - 同一分鐘內最多收 10 筆（用 CacheService 計數）
  - 每個欄位都有長度上限
- **同時寫入**：寫入時用 LockService 上鎖，避免兩筆資料同時寫入時互相覆蓋。
- **試算表公式注入**：文字開頭如果是 `= + - @`，會在前面加上單引號，避免被當成公式執行。

## 6. 官網表單的改動（script.js）
- 送出時改成 `fetch` 呼叫 Apps Script，不再打開 mailto。
- 送出過程中，按鈕停用並顯示「送出中…」。
- 成功：清空表單，顯示「已收到您的諮詢，我們會盡快與您聯繫」。
- 失敗（例如網路問題）：顯示「送出失敗，請稍後再試，或直接來電 0915-512-120／加 LINE」，表單內容保留。
- Apps Script 的網址放在 `config.js`。這個網址本身公開沒關係，因為只有 `submit` 動作不需要秘密碼。

## 7. 後台頁面（admin.html／admin.css／admin.js）
- **進入**：從網址 `#k=` 讀取秘密碼。
  - 沒有秘密碼或秘密碼錯誤：只顯示「網址不正確」，不顯示任何資料。
  - 頁面設定 `noindex`，不讓搜尋引擎收錄。
- **風格**：沿用 STYLE.md 的配色和字體，也支援深色模式。
- **頂部**：各進度的數量統計，點一下就篩選該進度。
- **列表**：
  - 顯示姓名、電話、工程類型、日期、進度
  - 最新的在最上面
  - 可以用關鍵字搜尋（姓名、電話、需求說明）
  - 電腦版是表格，手機版是卡片
- **詳細面板**（點開一筆）：
  - 顯示完整的需求說明
  - 電話可以一鍵撥出，Email 可以一鍵寄信
  - 可以改進度（下拉選單）和備註（文字框），按「儲存」後送出
  - 儲存成功或失敗都會顯示提示
- **手動新增**：按鈕打開表單，欄位和官網一樣，姓名和電話必填。
- **匯出**：按「匯出 Excel」下載 CSV 檔，檔案開頭加 UTF-8 BOM，讓 Excel 打開中文不會亂碼。
  - 匯出的範圍 = 目前篩選和搜尋後看到的資料
- **重新整理**：有按鈕可以重新抓最新資料。

## 8. 錯誤處理
- 讀取資料失敗：顯示錯誤訊息和「重試」按鈕，不顯示空白列表。
- 儲存失敗：保留剛輸入的內容，提示重試。
- 秘密碼錯誤：Apps Script 回傳 `unauthorized`，後台顯示「網址不正確」。

## 9. 使用者需要做的設定（我會提供逐步說明）
1. 建立 Google 試算表，貼上 Apps Script 程式碼。
2. 在指令碼屬性填入 `ADMIN_KEY`（我會幫你產生）和 `NOTIFY_EMAIL`。
3. 部署成網頁應用程式，第一次會要求你授權。
4. 把部署後的網址給我，我再放進 `config.js`。

## 10. 測試方式
- 部署完成後，實際從官網送出一筆測試諮詢，確認三件事：
  - 試算表有新增一列
  - 收到通知信
  - 後台列表看得到這筆
- 在後台修改進度和備註，重新整理後確認資料還在；再用手動新增一筆。
- 用錯誤的秘密碼打開後台，確認看不到資料。
- 匯出 CSV，用 Excel 打開確認中文正常。
- 測試完畢後，由站長決定要不要刪除測試資料（在試算表直接刪）。

## 11. 已知的風險（使用者已接受）
- 秘密網址一旦外流，拿到的人可以看到和修改資料。處理方式是更換 `ADMIN_KEY`。
- Apps Script 每次回應大約需要 1–2 秒。
- Google 每天寄信有額度限制（一般帳號約 100 封／天），以目前的諮詢量足夠。
